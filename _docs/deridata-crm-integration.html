DeriData API Integration in CRM

Bond Autofill — Two-Phase Calculator Flow (Management Brief)

Audience: Product / Ops / Leadership
Scope: CRM Bond Auto-Update Autofill only
Date: 10 Jul 2026

1. Purpose

DeriData is the external bond calculator used by MeraDhan CRM to price bonds during autofill. Ops reviews the suggested values and Accepts them onto the bond master record. Customer place-order and draft PDFs then reuse those saved CRM values (scaled by quantity) — they do not call DeriData live.

One-line summary: We call DeriData once to learn dates and decide shut period, then call again with the correct shut flag so price, accrued interest, and settlement amounts are consistent.

2. End-to-End Flow

CRM inputs (ISIN, settlement date, quantity, YTM or clean price) │ ▼ ┌──────────────────────────────────┐ │ Phase 1 — Probe calculator call │ cashflow_shut_flag = true │ Get record_date + cashflow dates │ └────────────────┬─────────────────┘ │ ▼ Local shut / accrual calculation → cashflow_shut_flag (true / false) → accrued days, coupon & record dates │ ▼ ┌──────────────────────────────────┐ │ Phase 2 — Pricing calculator │ cashflow_shut_flag = computed │ (or reuse Phase 1 if already OK) │ └────────────────┬─────────────────┘ │ ▼ Map money fields as-is → CRM Autofill UI On Accept → save sell price, yield, accrued ₹, stamp duty, pricing quantity, dates

4. Manipulation — Shut Period & Accrual Days

Between the two API calls, MeraDhan computes shut status locally from DeriData dates. This is the only business key we override and send back into Phase 2.

Manipulated key: cashflow_shut_flag
Set to our computed isUnderShutPeriod (not DeriData’s echo of the probe input).

Shut rule

Shut is ON when:
RECORD_DATE ≤ SETTLEMENT_DATE < NEXT_COUPON_DATE
Settlement on the coupon date → shut ON, accrual days = 0.
Output keyHow it is calculated
isUnderShutPeriod / cashflowShutFlag From shut rule above
accruedDays Shut: negative days from settlement → next coupon
Normal: positive days from last coupon → settlement
recordDate, lastCouponDate, nextCouponDate Parsed from DeriData record_date + cashflow dates
recordDays Calendar days between record date and next coupon
periodStatus "Shut Period" or "Normal"

5. Phase 2 — Pricing (Money Amounts)

API Call 2 — Same endpoint, corrected shut flag

Purpose: obtain final clean price, accrued interest, consideration, stamp duty, and settlement amount under the correct shut flag.

YTM mode

  • yield_to_price: true
  • ytm = CRM pricing yield
  • cashflow_shut_flag = computed

Clean-price mode

  • yield_to_price: false
  • clean_price = CRM clean price
  • cashflow_shut_flag = computed

Reuse optimisation: If Phase 1 already used cashflow_shut_flag = true and our computed shut is also true (YTM mode), Phase 1’s response is reused — no second network call (avoids timeouts).

After Phase 2, principal / accrued / consideration are not recalculated in-house. DeriData amounts are preferred and shown in CRM autofill.

6. What Happens After Accept

  1. Ops reviews autofill suggestions in CRM and Accepts.
  2. Bond master is updated with sell price, yield, accrued interest (₹), stamp duty, pricing quantity, and related dates.
  3. Customer place-order and draft order PDFs scale those saved values by order quantity. No live DeriData call on the customer path.

7. Why Two Calls?

Risk if we skip Phase 1Impact
Wrong cashflow_shut_flag sent to pricing Incorrect accrued interest (sign/amount) and settlement totals
Rely only on local coupon schedule Can disagree with DeriData record date → shut mismatch
Always double-call without reuse Slow CRM autofill / proxy timeouts under load
